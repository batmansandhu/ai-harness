One-paragraph summary

A webhook materializes into a typed Job. Deterministic Rust classifies it, enforces budget, and walks a fixed state machine: intake → classify → plan → [approve?] → execute → verify(HARD) → commit → log. The LLM step is one tool of twelve, invoked by shelling claude -p --output-format=stream-json. R3 (credential-touching) never reaches the LLM. Every job writes one NDJSON row so the eventual self-evolving loop has training data.

Stage 1 surface area

  • Live: W1 career-ops-scan — POSTs hit Axum, harness wraps existing batch-runner.sh (input.tsv → state.tsv → claude -p → reports + tracker). Reports land in projects/career-ops/output/; one NDJSON log row per job.
  • Provider: only SubscriptionClaude. Ollama via Aperture is wired but disabled until stage 2.
  • Memory: ephemeral by default. Cersei graph memory is opt-in per workflow; stage-1 workflows are all memory_scope: none.
  • Verify: hard-verify is non-negotiable. Soft-verify (LLM-as-judge) opt-in per workflow.

What this is not

  • Not a LangChain. There is no chain abstraction; there is one state machine.
  • Not an agent framework. The LLM is a tool, not the orchestrator.
  • Not metered API. Subscription Claude only. Cost is constant.
  • Not self-evolving (yet). §8 log schema is designed so the next stage can learn from job outcomes — that loop is deferred.
